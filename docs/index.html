Telegram Self-Bot & Account Management Platform

A modular, production-ready Telegram client with a modern web dashboard — message & media archiving, rule-based auto-reply, AI chat automation, account warming, neuro dialogs, smart forwarding, multi-account control, security center, backup/restore and much more.

Stack: FastAPI · Vue 3 · Telethon · SQLAlchemy · Redis · Celery API: REST + WebSocket Interface: English & فارسی (RTL) License: MIT

Installation

Works on Linux, macOS, Windows and Docker. Requires Python 3.11+, FFmpeg and Redis.

Get Telegram API credentials

Open my.telegram.org → API development tools → create an app. Copy the numeric api_id and the 32-character api_hash.

Install the project

  • Linux/macOS: chmod +x install.sh && ./install.sh
  • Windows: run .\install.ps1 in PowerShell
  • Manual: pip install -e ".[dev,ai,media]" then cp .env.example .env

Configure .env

Set TELEGRAM_API_ID, TELEGRAM_API_HASH, and strong random values for APP_SECRET_KEY, JWT_SECRET_KEY, ENCRYPTION_KEY, CSRF_SECRET_KEY. PostgreSQL is recommended for production.

Run migrations & create admin

python -m backend.app.main migrate
python -m backend.app.main init-admin   # admin / admin123

Start the server

python -m backend.app.main serve --reload

Dashboard → http://localhost:8000 · API docs → http://localhost:8000/api/docs

Docker (production path)

cp .env.example .env
# edit .env …
docker-compose up -d
docker-compose exec app python -m backend.app.main init-admin

Runs app + Celery worker + beat + Redis with healthchecks.

Security: change the default admin/admin123 password right after the first login, and never deploy with placeholder secrets.

Security

Built-in protections

  • JWT auth (30-min access + 7-day refresh tokens)
  • bcrypt password hashing + CSRF middleware
  • Rate limiting (30 req/min/IP) + audit logging
  • Session & backup encryption at rest
  • Emergency stop that halts all automation
  • Anti-abuse caps (per action / chat / user)

Recommended hardening

  • Random APP_SECRET_KEY / JWT_SECRET_KEY / ENCRYPTION_KEY / CSRF_SECRET_KEY
  • Change the default admin password immediately
  • Use PostgreSQL in production
  • Reverse proxy (nginx) + TLS in front
  • Monitor the Security Center & audit logs weekly

Troubleshooting

FloodWait errors

Telegram is throttling your account. Stop automation (Emergency Stop), wait out the penalty, then reduce intensity: increase broadcast delays (3–5 s+), lower max_responses_per_day, and warm up at beginner.

Dashboard blank / 404

The Vue frontend hasn't been built. Run cd frontend && npm install && npm run build, then restart and hard-refresh the browser.

Redis connection refused

Confirm with redis-cli ping (expect PONG) and align REDIS_URL. In Docker check docker-compose ps.

ModuleNotFoundError: backend

You're not on the project root, or the package isn't installed in editable mode. Run pip install -e ".[dev,ai,media]" and start from the root.

Tables missing / migration errors

Run python -m backend.app.main migrate. For a broken SQLite file, back up, remove storage/database.db, and re-migrate.

Rule of thumb: read storage/logs/app.log (or the dashboard Logs tab) first — the answer to almost every problem is printed there.

FAQ

Is this an "official" Telegram Bot API bot?
No. It connects through Telegram's MTProto (via Telethon) using your personal api_id/api_hash from my.telegram.org. It's a self-bot/userbot platform for managing your own account(s).
Is using a self-bot against Telegram's ToS?
Telegram formally discourages userbots; excessive spam/automation can lead to temporary FloodWait limits or restrictions. This platform includes Account Warming, rate limits, and an emergency stop specifically to help you stay within safe boundaries. Use responsibly.
Can I run multiple accounts from one dashboard?
Yes — the Multi-Account Manager keeps a registry of accounts each with its own API credentials and per-account toggles for auto-reply, warming, and chat automation.
Which AI providers work out of the box?
OpenAI, Google Gemini, DeepSeek, OpenRouter, and local LLMs (Ollama style) via LOCAL_LLM_URL. Install the AI extras with pip install -e ".[ai]".
Do I need Redis?
The dashboard and core archiving work without it, but schedulers, broadcasts, repeaters, backup jobs, and Celery workers require Redis. Use it — the Docker install makes it trivial.
Where is my data stored?
By default in storage/: SQLite database (database.db), media (media/), backups (backups/), and logs (logs/). All overridable in .env.
How do I recover if I forget the admin password?
From the server console run python -m backend.app.main init-admin (it recreates the default admin if missing), or reset the bcrypt hash directly in the database.
Is there a public API / Swagger?
Yes — Swagger UI at /api/docs, ReDoc at /api/redoc, and the OpenAPI schema at /api/openapi.json. Plus a WebSocket channel at /ws for real-time updates.
